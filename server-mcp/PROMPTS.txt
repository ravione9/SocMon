----------------------------------------------------------------------
  ROP SYSTEM DISCONNECT EVENTS — BH FILTER (Store Zabbix UI / REST)
----------------------------------------------------------------------

Source: MongoDB StoreProblemHistory (code='offline') — same data as
netpulse_storeProblems, but the Store Zabbix ROP dashboard applies an
explicit business-hours (BH) filter toolbar:

  UI location: Store Zabbix → ROP tab → click a store row → Disconnect
  events modal. Reports tab → group Excel export.

  Table columns (match Store Monitor / storeProblems MCP):
    # | Disconnected at | Back up at | BH duration | Total duration | Status

  BH filter params (REST query string):
    bizStart   — hour 0–23 start (default 9 = 09:00)
    bizEnd     — hour 0–23 end   (default 18 = 18:00)
    bizDays    — weekday CSV 0=Sun … 6=Sat (default 0,1,2,3,4,5,6)
    tzOffset   — minutes east of UTC (IST = 330)
    range      — 24h | 7d | 14d | 30d | 60d | custom
    from / to  — Unix seconds when range=custom

  Per-store events (one storeTag):
    GET /api/store-zabbix/rop-store-disconnects
      ?storeTag=<STORE-TAG>
      &range=7d
      &bizStart=9&bizEnd=18
      &bizDays=1,2,3,4,5
      &tzOffset=330

  Group Excel export (all stores in ROP group):
    GET /api/store-zabbix/rop-disconnect-export
      ?groupKey=rp|rp_sdwan|rp_no_sdwan|manual_sdwan|pos|sdwan
      &range=30d&bizStart=9&bizEnd=18&bizDays=0,1,2,3,4,5,6&tzOffset=330

  Single-store Excel export:
    GET /api/store-zabbix/rop-store-disconnect-export?storeTag=...&range=...

  BH filter rule: events with bhDurationMin <= 0 are EXCLUDED when BH is
  active (not 00:00–24:00 every day). "No events overlap BH window" means
  outages happened only outside configured business hours.

  MCP shortcut (default BH 09:00–18:00 IST, no custom bizDays):
    netpulse_storeProblems question: "disconnect events <STORE-HOSTNAME> 30 days"
    Use when BH = 9–18 all days. For Mon–Fri only or custom hours, use REST.

  storeTag vs hostname:
    REST rop-store-disconnects needs storeTag (e.g. RP793_… from storeMonitor).
    MCP storeProblems accepts hostname (RP793, LKST793) and applies alias filter.

----------------------------------------------------------------------
Store Zabbix ROP disconnect events for storeTag <STORE-TAG>, range 7d,

  "cpu <HOST>"       -> netpulse_storeZabbix + storeMonitor for dual-source
                        CPU/RAM; label Zabbix vs Influx agent.
  "trend <HOST>"     -> netpulse_storeZabbix 24h cpuMemoryHistory graph.
Always quote numbers verbatim from tool output. Never invent data.

================================================================================
  TIPS FOR BETTER RESULTS
================================================================================

  * Name the tool when you want to force its use. Claude sometimes prefers
    netpulse_query for everything; nudging it to a specific dashboard tool
    gives you raw module data instead of a summarized answer.

  * Phrase prompts as "...and quote numbers from the tool output" to stop
    Claude from rounding or paraphrasing counts.

  * Time bounds matter. NetPulse modules have different freshness ("live"
    vs "periodic"). "Last 5 minutes" works on storeMonitor (live InfluxDB);
    storeProblems is snapshotted every ~2 min so prefer "last hour" or longer.
    storeZabbix and zabbixInfra are live Zabbix API at send time.
    orian is live SolarWinds Orion SWIS at send time (requires ORION_* env).

  * Hostname in question unlocks scoped data:
      storeProblems  -> 30-day disconnect history for that store (not global 120 cap)
      storeZabbix    -> host filter + CPU/RAM + optional 24h cpuMemoryHistory
      storeMonitor   -> single-store live snapshot from Influx agent

  * LKST vs LK vs RP naming:
      LKST793  -> aliases to RP793 in Store Zabbix (LKST prefix only)
      LK973    -> strict LK host match (no RP alias)
      RP973    -> strict RP host match

  * CPU / Memory sources — do not conflate:
      Store PC       -> storeAgentMetrics / storeMonitor (Influx agent)
      Network gear   -> hosts[].cpu/memory in storeZabbix (Zabbix SNMP/agent)
      24h trends     -> cpuMemoryHistory (Zabbix history.get / trend.get)

  * Disconnect events use IST business hours (09:00–18:00) for bhDurationMin.
    All rendered timestamps should be stated as IST unless user asks otherwise.

  * Disconnect events — two paths:
      MCP storeProblems     -> disconnectEvents[] · default BH 09:00–18:00 IST
                               · hostname/LKST filter · 30-day scoped window
      Store Zabbix REST     -> rop-store-disconnects · custom BH toolbar
                               · needs storeTag · range 24h–60d · Excel export
      Same Mongo source (StoreProblemHistory code=offline). BH filter drops
      events where bhDurationMin=0 (outage did not overlap BH window).

  * If disconnectEventsTruncated is true in storeProblems, re-query with the
    store hostname (e.g. LKST793) instead of relying on the global list.

  * For long replies, ask for "under 200 words" or "as a table" -- keeps
    output scannable in Claude Desktop.

  * Module-specific prompts beat generic ones when you know the domain.
    Claude wastes fewer tokens picking modules.

  * REST equivalents (for scripts, not Claude):
      GET /api/store-zabbix/rop-store-disconnects?storeTag=&range=&bizStart=&bizEnd=&bizDays=&tzOffset=
      GET /api/store-zabbix/rop-disconnect-export?groupKey=rp&range=30d&...
      GET /api/store-zabbix/rop-store-disconnect-export?storeTag=&range=...
      GET /api/store-zabbix/items/{itemId}/history?from=&to=
      GET /api/store-zabbix/graphs/{graphId}/series?from=&to=
      GET /api/store-monitor/stores  (live Influx snapshot)
